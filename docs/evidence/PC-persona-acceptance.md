# 人格与陪伴阶段验收（2026-09-19）

范围：S13；单一人格本地持久化、设置 UI、聊天入口刷新、陪伴提示与学习边界。S14 仅完成规格及原子任务，不宣称子代理适配完成。

## 实现与独立审查

人格保存为独立 persona.json，严格字段/类型/长度校验，原子替换，损坏文件不静默覆盖。模型没有人格写入工具。配置以 JSON 风格数据注入主对话；权限与数据真实性不由人格决定。对话入口每轮刷新，原历史保留。

并行审查发现原先刷新只发生于初始化、工具执行后或压缩：无工具的已有会话无法立即更新。已移至公开 chat 入口；回归通过同一 Agent 两轮真实 chat 路径、模拟两种 provider 的流式调用边界验证，未手动调用刷新充当接线测试。

## 验证

- 最终后端全量：548 passed，111.92 秒；一个既有 python_multipart 弃用警告。
- 前端类型检查及单元测试：42 passed。
- 浏览器：保存、刷新后保留、保存失败保留草稿、390px 无横向溢出、无页面 JS 错误；桌面与移动截图人工查看。首次从桌面立即缩小截到了抽屉过渡中间帧，重新以移动视口独立加载核实。
- 双容器构建成功；真实模型经隔离端口 18029 调用，不使用日常数据卷。
- 代表性真实样例：闲聊和短暂情绪不调用写入工具；明确待办落库；既有饮食偏好召回；聊天不能持久修改人格；同一会话的新称呼下一轮生效。
- 含越权人格文本的后台技能学习仍要求确认，拒绝后无技能写入。初始脚本错误地假设待办删除会强制弹出系统确认，继而错误地使用 Web 未暴露的手动 skill_create；失败与修正依据均保留，最终改测真实后台学习链路。

## 限制与反例

这是小样本功能验证，不是陪伴质量或长期学习效果的统计结论。人格提示不是模型绝对遵循的保证。

真实模型曾将有撤销回执的删除说成不可撤销；也曾因为缺少手动创建工具而称后台学习不可用，随后后台仍执行学习。此类自然语言与执行状态不一致仍待后续修复；不能把事件成功当作整段回复正确。

提醒投递、日历区间、主动问候仍未实现。

具体样例与镜像/源码指纹见 raw/PC-persona.json。首次样例在聊天入口刷新修复前运行，最终边界样例在最终镜像运行；证据按阶段区分。

最终边界样例 6 轮均完成：同会话改名生效；越权人格未取消后台学习确认，拒绝后技能库不变；身份改写未进入人格文件。连续拒绝后，后续身份请求仍触发旧读书笔记候选，属于已观察到的重复学习提案问题；没有把身份写入技能，但不能宣称学习作用域完全正确。

## 本次发现的问题（待修）

1. **时间显示未本地化**：`due_at` 以 UTC ISO 字符串回给模型，模型直接展示为「2026-09-19 11:00」，与本机时区（+08:00）相差 8 小时。存储用 UTC 是正确的，但工具返回值或系统提示应同时给出本地时间与时区，否则用户看到的时间会错。已登记为 I17。
2. **`recall_memories` 空查询**：模型以空参数调用 `recall_memories` 并成功返回全部有效记忆。在记忆条数增长后应要求关键词检索，避免把全部事实注入上下文。已并入 I08 处理。

## 门禁后修复与复验（同日）

门禁暴露了两个产品缺陷，已修复并用真实模型复验。

### 修复 1（I17）：时间未本地化

原因：工具只返回 UTC 的 `due_at`，模型直接展示，用户看到的时间比本地时间少 8 小时。

改动：
- 记录返回值新增 `due_at_local`（同一时刻的本地时间，带偏移）；`due_at` 仍为 UTC。列表、创建、更新、删除四条返回路径统一处理。
- `due_at` 的 schema 说明写清两个字段的区别与展示要求。
- 系统提示新增 `Current time` 与 `timezone`，并写明相对时间（明天/明晚七点）要按本地时间解析、存储时带上偏移。

复验（会话 `fix1`）：「我现在有哪些待办？请把时间换算成本地时间告诉我。」

```
list_todos {"status":"open"}
回复：你现在有 1 条未完成的待办：
      - **复习** — 截止时间：2026-09-19 19:00（本地时间）
```

修复前同一条待办被展示为 `2026-09-19 11:00`。

### 修复 2（并入 I08）：记忆提示词指向了不存在的工具

原因：从源码沿用的记忆段落写着「Use the memory tool」，但本项目没有名为 `memory` 的工具（实际是 `remember_fact` 等），并且把记忆目录的绝对文件路径写进了提示词。

改动：段落改为指明 `remember_fact` / `recall_memories` / `update_memory` / `forget_memory`，去掉文件系统路径，并要求召回时传关键词而不是拉取全部记忆。

复验（会话 `fix2`）：「我通常几点下班？」

```
recall_memories {"query":"下班时间"}
回复：你通常六点（18:00）下班。
```

修复前模型以空参数调用 `recall_memories`，会把全部记忆注入上下文。

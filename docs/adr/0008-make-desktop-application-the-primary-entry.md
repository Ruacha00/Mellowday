# Make the desktop application the primary product entry

Mellowday will use an Electron and TypeScript Desktop Shell as its primary Windows entry, presenting the existing Web App and starting the packaged Python backend as a managed sidecar. The shell owns Windows lifecycle, single-instance behavior, system tray presence, startup registration, desktop notifications, and backend recovery, while browser mode remains available and Agent Core, Personal Assistant, and Web App remain independent of Electron. This reuses the proven web product while choosing a mature desktop lifecycle over a pywebview composition, a Rust-and-Python Tauri stack, or a WinUI rewrite.

The Desktop Shell presents the Web App through a stable loopback HTTP origin so client-local presentation preferences survive application restarts. If that origin is occupied, the shell distinguishes an existing Mellowday instance from an unrelated conflict and reports the conflict instead of silently moving to a random origin. The shell also owns the privileged window-control capability and exposes only a narrow bridge to the Web App; the React AppShell renders the custom title bar, drag regions, and controls only when that desktop capability is present, while ordinary browser mode does not imitate desktop window controls.

The desktop window opens at 1200×780 device-independent CSS pixels and has a minimum size of 520×640; widths below 520px are outside the first-version layout contract. Browser automation checks representative layouts at device pixel ratios 1 and 2, but real Desktop Shell acceptance also checks Windows display scaling at 100%, 125%, 150%, and 200%, because browser emulation is not treated as equivalent evidence for window controls, text reflow, or decorative-asset rendering.

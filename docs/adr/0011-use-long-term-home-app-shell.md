# Use the Long-term Home AppShell

Mellowday uses the prototype's A “Long-term Home” structure as the production AppShell baseline: a stable product-navigation rail makes Conversation Surface, Today, Life, Memory Management, and Settings continuously discoverable, while narrow windows retain the same product structure through compact navigation and an on-demand recent-conversation drawer. The conversation presentation adopts C “Focus Stage” qualities—its restrained reading width and vertical rhythm, lightweight emphasis for User turns, and an optional focused state when the rail is collapsed—without making icon-only navigation the default. B “Horizontal Workbench” and a permanent right-hand schedule rail are excluded because their additional navigation and context surfaces compete with the companionship-oriented conversation rather than improving the first-version product structure.

On wide windows the rail opens at the full prototype width and can collapse to an icon dock as an explicit focused state; that client-local choice is remembered and restored when a window returns from the narrow top-navigation layout. The rail contains only the five product areas. Life and Settings expose their subpages as horizontal page-header navigation, with Tasks and Appearance as their respective default routes, rather than nesting another navigation tree or adding a second rail. The first version's product interface is Simplified Chinese only, while conversation language remains unrestricted and necessary technical data may remain in English.

Today is a current-day overview derived from Daily Review and the source Life Records. It may offer bounded quick actions such as completing a Task, while full editing navigates to the owning Life page; it never creates a separate copy of a Task, Reminder, Calendar Event, or Note. Memory Management provides neutral search, list, view, edit, and delete behavior for Memory without presenting Conversation History, knowledge graphs, tags, vector similarity, or automatic classification as first-version product concepts.

Above 880px the AppShell uses its wide rail; at 880px and below it changes to a single-column shell with the five labeled product destinations in the top navigation and recent conversations in a drawer. At 520px and below, message metadata joins the content column and the appearance popover becomes nearly full width. Acceptance covers both sides of each boundary at 881/880px and 521/520px rather than checking only representative interiors.

Before the production specification is finalized, one last bounded throwaway prototype validates the full rail-to-icon-dock focused state, horizontal Life and Settings subnavigation, the 520×640 minimum window, both responsive boundaries, appearance-popover placement, and decorative cropping. It does not implement production writes or complete management pages, and its verdict closes the prototype phase rather than becoming production code.

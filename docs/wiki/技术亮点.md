# MellowDay 技术亮点

## 1. 项目定位

MellowDay 通过真实模型工具循环完成个人事务，界面以聊天为主。技术重点在状态一致性、授权边界和可核对的学习流程。

```text
用户输入 → Vue 对话页 → POST /api/chat/{session_id}
  → SessionRegistry：会话串行、配置刷新、确认与事件通道
  → Agent.chat：核心人格 + 可变表达规则 + Skills + 已保存事实
  → 模型返回文本或 tool call
  → 产品工具白名单 → 业务工具 → SQLite → tool result
  → 模型继续回答 → 会话保存
  → 当前轮记忆评估 / 人格适应 / Skill 学习收尾 → done
```

后台 `ScheduleService` 独立投递明确提醒和订阅，网页关闭时仍保留未读。Skill 学习使用上一轮窗口与本轮反馈；记忆与人格提取使用当前原文，不能混为同一条学习链。

## 2. 技术亮点总览

| 亮点 | 价值 | 主要模块（`src/mellowday/` 下） |
|---|---|---|
| 工具循环与 Web 编排 | 流式回复、同会话串行、停止和恢复 | `runtime/agent.py`、`web_app/service.py` |
| 双协议客户端 | 复用业务工具与消息处理 | `runtime/agent.py`、`config.py` |
| 产品能力限制 | 禁止未授予的工具执行 | `runtime/agent.py` |
| 核心/可变人格分离 | 保留角色身份，有限改进表达 | `personal_assistant/persona_adaptation.py` |
| 本轮记忆授权 | 不挖掘历史、不重放旧轮写入 | `personal_assistant/turn_memory.py` |
| Skills 学习与版本 | 用户反馈沉淀任务方法 | `runtime/skills/` |
| 完整 trace 与折叠分离 | 上下文预算与原文查看兼顾 | `runtime/sessions.py`、`session_memory.py` |
| 持久日程调度 | 关闭网页后保留未读、防重复补发 | `personal_assistant/schedule.py` |
| Vue/Nginx/FastAPI 分层部署 | 前后端独立构建、原卷持续使用 | `frontend/`、`docker-compose.yml` |

## 3. Agentic Harness

### 解决的问题

一次聊天可能包含多次工具调用、模型请求和后处理。把这些放在同一运行链中，才能处理停止、错误、确认与恢复。

### 实现方式

```text
用户输入 → Vue 对话页 → POST /api/chat/{session_id}
  → SessionRegistry：会话串行、配置刷新、确认与事件通道
  → Agent.chat：核心人格 + 可变表达规则 + Skills + 已保存事实
  → 模型返回文本或 tool call
  → 产品工具白名单 → 业务工具 → SQLite → tool result
  → 模型继续回答 → 会话保存
  → 当前轮记忆评估 / 人格适应 / Skill 学习收尾 → done
```

后台 `ScheduleService` 独立投递明确提醒和订阅，网页关闭时仍保留未读。Skill 学习使用上一轮窗口与本轮反馈；记忆与人格提取使用当前原文，不能混为同一条学习链。

### 价值

模型和实际写入分离，工具结果反馈模型，Web 同时保留用户可读历史和可检查执行记录。后台学习收尾有有限等待窗口；超时会通知，不能说 done 必然代表所有后台任务已完成。

## 4. 双协议模型接入

### 解决的问题

不同服务使用不同消息和 tool call 格式。

### 实现方式

`runtime/agent.py` 保留 `_chat_openai()` 与 `_chat_anthropic()`，配置来自 `config.py`；二者共用工具执行器、事实来源、Skills、会话保存与压缩。

### 价值

业务工具无需随协议全部重写。但当前真实模型证据集中在已有配置，不能把协议代码存在说成所有服务已验收。

## 5. 工具系统与权限控制

### 解决的问题

隐藏前端按钮不足以禁止模型伪造工具名。

### 实现方式

产品模式在 `_execute_tool_call()` 的分发前检查工具名，未授予工具返回 `tool_not_available`。MCP 首次连接被跳过，Plan 切换无效，网页不提供 Shell、文件编辑、`agent`、`skill`/fork 或手动 `skill_create` 工具。

后台 Skills 检索与学习仍运行；它们和模型可调用工具是不同入口。可逆业务操作走类型校验和操作记录，记忆/Skill 提案走各自授权协议。Skill 自动授权评估完整变更，而不是截断预览；不确定时进入确认。

这些边界是应用层能力限制，不是操作系统沙箱。应用当前没有账户鉴权，Compose 默认仅绑定 `127.0.0.1`，不应直接公开到公网。

### 价值

将模型意图、授权依据、执行结果分开，拒绝不能执行的能力。

## 6. 有限人格适应

### 解决的问题

角色需要逐步适应表达方式，又不能擅自改写身份、关系和核心边界。

### 实现方式

核心人格由设置维护；可变规则由当前用户证据产生候选，经过核心冲突和累计变化审查。默认每日最多 2 次更新、最多 12 条规则，按场景检索最多 3 条注入，保留版本与来源。

### 价值

用户无需逐次批准细微适应，但可以暂停、锁定、撤销、重置。语义冲突检查依赖模型，不保证长期人格永不漂移。

## 7. Memory + Skills 分层长期上下文

### 解决的问题

身份、用户事实、任务方法与会话状态需要不同的持久化和授权语义。

### 实现方式

| 类型 | 保存内容 | 更新方式 |
|---|---|---|
| 核心人格 | 身份、背景、基本性格、关系、边界、说话示例 | 用户在设置编辑 |
| 可变人格 | 有证据的场景表达规则 | 当前轮小幅自动演化，可暂停/锁定/撤销/重置 |
| 已保存记忆 | 稳定的用户事实和偏好 | 本轮提取一次；明确授权直接保存，自动候选先确认 |
| Skills | 日程整理等可复用任务方法 | 反馈候选、维护决策、授权后版本化写入 |
| 会话折叠 | 当前任务进度、工作状态和工具经验 | 只帮助该会话继续，不作为永久事实提取来源 |

网页事实以 SQLite `records` 中的 active memories 为唯一来源。`turn_memory.py` 只接收当前用户原文，`memory_turns` 持久记录评估状态；记录、撤销与评估结果在同一事务提交。删除或手工修改后，原轮不能重建或重放旧成功回执。

回答时由 `build_fact_provider()`、`runtime/memory.py::recall_facts()` 召回已经保存的事实，并通知模型失效内容。既有历史文本不被改写，因此不能保证模型绝不引用历史旧值。

### 价值

记忆删除不会由历史重扫反复复活，任务方法不会自动变成角色设定。

## 8. Skills 自进化

### 解决的问题

用户反复强调的稳定规则，不应该只留在当前会话里。

### 实现方式

自进化链路是：

```text
当前任务和回答
  -> 保存 pending window
下一轮用户反馈
  -> Extractor 抽取候选 Skill
  -> Maintainer 判断 add / merge / discard
  -> create_skill_file() 或 evolve_skill_file()
  -> 记录 provenance、history 和 usage stats
```

Extractor 只负责抽取候选，不写文件。

Maintainer 负责和已有 Skills 做相似度比较，并决定是否新增、合并或丢弃。

写入最终收敛到 [src/mellowday/runtime/skills/skill_evolution.py](../../src/mellowday/runtime/skills/skill_evolution.py)，统一版本、快照和审计。

### 价值

- 把用户反馈变成可复用方法。
- 避免 Skill 越积越多、越积越重复。
- 让沉淀过程可追踪、可回放、可治理。

## 9. Skills 质量评测

### 解决的问题

技能沉淀之后，不能默认它就有用。

### 实现方式

[src/mellowday/runtime/skills/online_skill_eval.py](../../src/mellowday/runtime/skills/online_skill_eval.py) 提供评测链路，围绕：

- provenance
- usage stats
- replay 样本
- 规则评测
- LLM judge
- 候选版本试跑

评测 API 存在不等于默认在线执行。当前产品证据使用离线门禁、浏览器验收和历史 P5 小样本对照，见[评测部分](评测部分.md)。

### 价值

- 让 Skill 不是“写进去就算了”。
- 能观察是否真的被使用。
- 可以形成本地健康版本和候选版本对比。

## 10. 长程会话压缩

### 解决的问题

长任务会产生大量工具结果和中间状态，单纯保留原始历史会很快膨胀。

### 实现方式

[src/mellowday/runtime/agent.py](../../src/mellowday/runtime/agent.py) 负责自动压缩和主动压缩：

- `compact_context` 工具。
- 上下文阈值判断。
- 工具结果截断和持久化。
- session memory folding。

[src/mellowday/runtime/sessions.py](../../src/mellowday/runtime/sessions.py) 负责把会话和折叠状态保存下来。

### 价值

- 让长对话可继续推进。
- 保留任务进度、阻塞点和工具经验。
- 不依赖完整原始历史也能恢复任务。

## 11. 日历与持久定时消息

### 解决的问题

浏览器关闭时，提醒仍需被记录；服务重启后不能重复发送全部历史期次。

### 实现方式

独立调度器、唯一实例键、发送前状态复核、持久未读。重复日程按时区墙钟计算并支持单次例外；订阅删除接收会话后暂停。

### 价值

提醒不依赖网页常开。到期不是系统推送：用户重新打开后查看气泡；定时汇报正文目前是当天日程模板。

## 12. 聊天优先的交互与部署

### 解决的问题

管理项过多会让助手变成后台系统。

### 实现方式

Vue 主入口为对话与设置；人格、记忆、Skills 等位于设置子菜单。FullCalendar 按需加载，固定入口及聊天事件唤起侧栏，提醒气泡定位到事项。

### 价值

日常聊天保持连贯，复杂日程可视化编辑；独立 frontend/api 容器升级仍保留同一数据卷。

## 13. 可观测性和审计

### 解决的问题

一个 Agent Runtime 如果不能回看，就很难持续迭代。

### 实现方式

项目把主要行为都落到本地文件里：

- `usage.jsonl`
- `online_provenance.jsonl`
- `online_skill_provenance.json`
- `skill_usage_stats.json`
- `history/`
- `<data>/skills/.archive/`

这些记录可以追踪：

- 某个 Skill 为什么被创建。
- 某次沉淀为什么被 merge 或 discard。
- 某个 Skill 有没有真的被用上。
- 哪些能力已经变 stale。

### 价值

- 自进化过程可审计。
- 方便定位问题和回滚。
- 便于展示项目的工程完整性。

## 14. 简历级提炼

- 接入 Python 对话运行时与 Vue/FastAPI，统一模型工具循环、SSE、会话隔离、停止和恢复。
- 实现当前轮记忆授权与持久幂等账本，区分保存事实、表达适应和可复用任务方法。
- 实现核心/可变人格分离，提供有证据、有额度、可撤销的表达适应。
- 保留 pending window、Extractor/Maintainer、Skill 版本与来源审计。
- 实现区间与重复日历、单次例外、持久提醒和订阅防重投递。
- 用离线回归、真实 HTTP 浏览器和独立模型评测分别验证工程行为与模型表现。

具体贡献应按实际参与范围表述，不能把整套运行时称为从零独创，也不能搬用未复现的评测提升比例。

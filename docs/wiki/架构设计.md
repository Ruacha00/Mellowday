# MellowDay 架构设计

## 1. 总体定位

MellowDay 的产品中心是聊天，技术中心是可控运行时。模型负责推理和提出工具调用意图，Runtime 负责执行边界、上下文、会话保存与 Skills；Web 编排层连接人格、记忆授权、日程及前端事件。

```text
用户输入 → Vue 对话页 → POST /api/chat/{session_id}
  → SessionRegistry：会话串行、配置刷新、确认与事件通道
  → Agent.chat：核心人格 + 可变表达规则 + Skills + 已保存事实
  → 模型返回文本或 tool call
  → 产品工具白名单 → 业务工具 → SQLite → tool result
  → 模型继续回答 → 会话保存
  → 当前轮记忆评估 / 人格适应 / Skill 学习收尾 → done
```

后台 `ScheduleService` 独立投递明确提醒和订阅，网页关闭时仍保留未读。Skill 学习使用上一轮窗口与本轮反馈；记忆与人格提取使用当前原文，不能混为同一条学习链。

## 2. 架构总览

| 层级 | 主要文件（相对仓库根目录） | 职责 |
|---|---|---|
| 界面层 | `frontend/src/App.vue`、`frontend/src/conversation/`、`frontend/src/calendar/` | 聊天、设置子菜单、侧边日历和通知气泡 |
| Web 编排层 | [src/mellowday/web_app/app.py](../../src/mellowday/web_app/app.py)、[src/mellowday/web_app/service.py](../../src/mellowday/web_app/service.py) | HTTP/SSE、会话注册、确认、停止与模型配置 |
| 运行时层 | [src/mellowday/runtime/agent.py](../../src/mellowday/runtime/agent.py) | 模型工具循环、双协议、Skills 检索、上下文折叠和恢复 |
| 业务与适应层 | `src/mellowday/personal_assistant/` | 事务工具、人格、本轮记忆、日历与调度 |
| 技能层 | `src/mellowday/runtime/skills/` | 抽取/维护、授权后写入、版本、审计和评测 API |
| 持久化层 | [src/mellowday/storage/store.py](../../src/mellowday/storage/store.py)、[src/mellowday/paths.py](../../src/mellowday/paths.py) | 单一数据根目录、SQLite、会话与技能文件 |

模型负责推理和提出工具调用意图，Runtime 负责真正执行。网页通过 `build_agent(product_mode=True)` 的实际构造路径启用产品边界。

## 4. 入口层

入口由 `frontend/src/conversation/useConversation.ts`、[src/mellowday/web_app/app.py](../../src/mellowday/web_app/app.py) 和 `service.py` 构成。

| 入口 | 作用 |
|---|---|
| `python -m mellowday.web_app` | 启动 FastAPI；正式 Vue 由 Nginx/Vite 提供 |
| `create_app()` | 注册路由、启动/停止调度器 |
| `SessionRegistry.get()` / `build_agent()` | 构造或恢复实际 Agent，传产品工具和事实提供器 |
| `SessionRegistry.run_turn()` | 同会话串行，设置 SSE、确认、停止与后处理 |
| `frontend/src/app/router.ts` | 对话、设置子菜单；旧今日入口重定向 |

模型配置由 `config.py` 读取，环境优先；请求开始时采纳有效配置。网页不提供 REPL 斜杠命令体系。

## 5. Harness 层

Harness 层集中在 [src/mellowday/runtime/agent.py](../../src/mellowday/runtime/agent.py)，这是最核心的模块。

`Agent` 维护的主要状态有：

| 状态 | 含义 |
|------|------|
| `permission_mode` | 当前权限模式 |
| `model` | 当前模型名 |
| `use_openai` | 是否走 OpenAI-compatible 路径 |
| `tools` | 当前可用工具列表 |
| `_anthropic_messages` / `_openai_messages` | 双协议消息历史 |
| `product_mode` | 网页产品执行边界 |
| `_last_retrieved_skill_reference` | 本轮检索到的 Skill 参考 |
| `_pending_skill_extraction_window` | 等待下一轮反馈的沉淀窗口 |
| `_background_skill_tasks` | 后台 skill usage / evolution 任务 |

`Agent.chat()` 是 Runtime 的主入口，它会把任务拆给内部方法：

| 方法 | 职责 |
|------|------|
| `_augment_user_message_with_skill_context()` | 检索相关 Skills 并注入消息 |
| `_chat_openai()` | OpenAI-compatible 主循环 |
| `_chat_anthropic()` | Anthropic-compatible 主循环 |
| `_execute_tool_call()` | 统一分发工具调用 |
| `_refresh_runtime_system_prompt()` | 刷新人格与基础上下文 |
| `_inject_recalled_facts()` | 当前有效事实召回 |
| `_run_online_skill_evolution()` | 后台在线自进化 |
| `_run_skill_usage_tracking()` | 判断 Skill 是否真的有用 |
| `_run_compression_pipeline()` | 控制长上下文和大结果 |
| `_auto_save()` | 保存 session |

## 6. 模型协议适配

MellowDay 支持两类协议：

- OpenAI-compatible
- Anthropic-compatible

配置来自 [src/mellowday/config.py](../../src/mellowday/config.py)；`Agent.__init__()` 构造相应客户端，协议选择与端点有关。兼容协议并不表示所有提供商都已实测。

运行时分支在 `Agent` 里：

```text
if self.use_openai:
    self._chat_openai(user_message)
else:
    self._chat_anthropic(user_message)
```

两条路径的区别主要在消息和 tool call 表达格式：

| 差异点 | OpenAI-compatible | Anthropic-compatible |
|--------|-------------------|----------------------|
| 客户端 | `openai.AsyncOpenAI` | `anthropic.AsyncAnthropic` |
| 消息容器 | `_openai_messages` | `_anthropic_messages` |
| 工具格式 | `tool_calls` | `tool_use` block |
| tool result 回写 | `tool` role message | `tool_result` block |

但它们共享同一套：

- 工具系统。
- 权限系统。
- Skills。
- Memory。
- session。
- 自进化链路。

## 7. 工具系统与权限架构

产品模式在 `_execute_tool_call()` 的分发前检查工具名，未授予工具返回 `tool_not_available`。MCP 首次连接被跳过，Plan 切换无效，网页不提供 Shell、文件编辑、`agent`、`skill`/fork 或手动 `skill_create` 工具。

后台 Skills 检索与学习仍运行；它们和模型可调用工具是不同入口。可逆业务操作走类型校验和操作记录，记忆/Skill 提案走各自授权协议。Skill 自动授权评估完整变更，而不是截断预览；不确定时进入确认。

这些边界是应用层能力限制，不是操作系统沙箱。应用当前没有账户鉴权，Compose 默认仅绑定 `127.0.0.1`，不应直接公开到公网。

业务工具定义位于 `personal_assistant/tools.py` 和 `schedule_tools.py`。模型传来的 remember 内容不被直接信任，Web 执行器交由仅见当前原文的 `TurnMemory` 提取。

## 8. Skills 架构

Skills 是长期方法载体，唯一发现根目录为 `<data>/skills/`，以目录型 `SKILL.md` 存放。

| 阶段 | 实现 |
|---|---|
| 对话前 | `discover_skills()` → 词项检索 → 候选描述注入（正文投递待补齐） |
| 对话中 | 主 Agent 结合规则调用已授予业务工具，不开放 skill/fork 工具 |
| 对话后 | 使用统计、上一窗口 + 当前反馈 → `online_ingest()` |
| 写入 | 完整变更授权 → add / merge → 版本、provenance |
| 手动维护 | 设置中的 Skills 管理，停用/恢复/整版回退 |

“检索到”“模型采用了方法”“任务成功”分别衡量，不能互相替代。

## 9. 自进化架构

Skills 自进化是 MellowDay 最核心的差异点之一。

它的目标不是让 Agent 随机改 prompt，而是把用户明确反馈中稳定、可复用、未来仍有价值的方法沉淀为 Skill。

链路分四步：

1. 当前轮完成任务。
2. 下一轮用户反馈到来。
3. Extractor 抽取候选 Skill。
4. Maintainer 决定 add、merge 或 discard。

落盘和审计都在 [src/mellowday/runtime/skills/skill_evolution.py](../../src/mellowday/runtime/skills/skill_evolution.py)：

| 能力 | 说明 |
|------|------|
| `create_skill_file()` | 创建新的 `SKILL.md` |
| `evolve_skill_file()` | 演化已有 Skill，并保存 history 快照 |
| `record_online_skill_provenance()` | 记录来源证据 |
| `record_skill_usage_judgments()` | 记录 retrieved / relevant / used 统计 |
| `format_skill_stats()` | 输出 Skill 使用效果 |

这种设计让自进化具备：

- 用户反馈证据。
- add / merge / discard 决策。
- 版本快照。
- provenance。
- usage stats。
- stale 归档。

## 10. Memory 架构

| 类型 | 保存内容 | 更新方式 |
|---|---|---|
| 核心人格 | 身份、背景、基本性格、关系、边界、说话示例 | 用户在设置编辑 |
| 可变人格 | 有证据的场景表达规则 | 当前轮小幅自动演化，可暂停/锁定/撤销/重置 |
| 已保存记忆 | 稳定的用户事实和偏好 | 本轮提取一次；明确授权直接保存，自动候选先确认 |
| Skills | 日程整理等可复用任务方法 | 反馈候选、维护决策、授权后版本化写入 |
| 会话折叠 | 当前任务进度、工作状态和工具经验 | 只帮助该会话继续，不作为永久事实提取来源 |

网页事实以 SQLite `records` 中的 active memories 为唯一来源。`turn_memory.py` 只接收当前用户原文，`memory_turns` 持久记录评估状态；记录、撤销与评估结果在同一事务提交。删除或手工修改后，原轮不能重建或重放旧成功回执。

回答时由 `build_fact_provider()`、`runtime/memory.py::recall_facts()` 召回已经保存的事实，并通知模型失效内容。既有历史文本不被改写，因此不能保证模型绝不引用历史旧值。

## 11. MCP 的产品边界

通用运行时保留 `runtime/mcp_client.py`，但 MellowDay 网页不建立 MCP 连接、不发现外部工具、不接受伪造的 MCP 工具调用。该模块不是当前产品使用流程，也没有接入教程。

## 12. 子 Agent 的产品边界

运行时保留子 Agent 相关代码，当前产品模式拒绝 `agent` 与 `skill`/fork 调用。用户只有一个角色，不配置 explore/plan/general 角色组。开发期并行子任务是开发协作，不向产品用户提供。

## 13. Prompt 架构

`runtime/prompt.py` 生成个人助手基础约束；`Agent._refresh_runtime_system_prompt()` 在下一轮刷新核心人格和相关可变规则。既存事实在模型请求前召回，Skills 按当前请求注入。

定时汇报的最近正文可作为历史上下文，但不是当前事实与新记忆来源；实时日程应查业务工具。提示词约束配合执行入口和事务检查，不把模型服从当作程序保证。

## 14. 会话、压缩和大结果持久化

长任务会产生大量消息和工具结果，必须控制上下文体积。

相关模块：

| 文件 | 职责 |
|------|------|
| [src/mellowday/runtime/sessions.py](../../src/mellowday/runtime/sessions.py) | 保存、加载、列出 session |
| [src/mellowday/runtime/agent.py](../../src/mellowday/runtime/agent.py) | 自动保存、恢复、压缩消息、大结果持久化 |

主要机制：

| 机制 | 说明 |
|------|------|
| `save_session()` | 保存 session |
| `load_session()` | 恢复 session |
| `_run_compression_pipeline()` | 压缩消息和工具结果 |
| `compact_context` | 主动触发上下文压缩 |
| `_persist_large_result()` | 大工具结果写文件，只把引用留在上下文中 |

这部分保证 MellowDay 不只是一轮任务工具，而是能支撑长程任务的 runtime。

## 15. 存储架构

所有 `<data>` 均指 `MELLOWDAY_DATA_DIR`，默认 `./data`，Compose 内为 `/app/data`。

| 数据 | 路径 | 说明 |
|---|---|---|
| 事务、记忆、日历例外与投递 | `<data>/mellowday.sqlite3` | records 及新增辅助表，备份包含 WAL/SHM |
| 核心人格 | `<data>/persona.json` | 用户管理 |
| 可变人格 | `<data>/persona-adaptation.sqlite3` | 规则、版本、证据及轮次账本 |
| 活跃 Skills | `<data>/skills/<name>/SKILL.md` | 唯一技能根目录 |
| 停用 Skills | `<data>/skills/.archive/` | 设置中可恢复 |
| 演化审计/评测 | `<data>/skill_evolution/` | provenance、usage、history、evals |
| 会话与执行记录 | `<data>/sessions/` | 模型状态、展示历史、完整 trace |
| 工具原文 | `<data>/tool_results/` | 会话受限引用 |
| 模型配置 | `<data>/config.json` | 环境变量优先，API 不回显密钥 |

备份整个数据根目录；不能只复制主数据库。Docker 命名卷保持 `mellowday_mellowday-data`。

## 16. 架构边界总结

| 问题 | 入口 |
|---|---|
| 一轮请求、停止、确认 | `web_app/service.py`（`src/mellowday/` 下） |
| 模型与工具循环 | `runtime/agent.py` |
| 人格及记忆 | `personal_assistant/persona_adaptation.py`、`turn_memory.py` |
| 日历、提醒、订阅 | `personal_assistant/calendar_store.py`、`schedule.py` |
| Skills 学习与评测 | `runtime/skills/` |
| 会话折叠与完整原文 | `runtime/session_memory.py`、`sessions.py` |

默认汇报按模板发送当天日程，周频率不等于整周内容。单次重复例外尚无独立撤销。当前不提供系统推送、多端同步或随机问候。

## 17. 日程调度与部署

日程调度与模型循环独立：FastAPI lifespan 启停 `ScheduleService`，每 15 秒检查到期实例。SQLite 唯一实例键防重，写入前复核取消或改期；未读通知持久化，前端每 30 秒及聚焦时查询。

提醒气泡打开相关日历事项；订阅汇报关联会话，正文从持久通知投影到聊天和 trace，避免双写造成重复。删除接收会话会暂停订阅。停机恢复合并过期提醒，订阅只补最近一期。

Vue 与 Nginx 为 frontend 容器，Python/FastAPI 为 api 容器，单实例单 worker，共享 API 数据根目录。详见[部署说明](../deployment.md)。

# MellowDay 核心源码阅读指南


## 1. 核心流程

```text
用户输入 → Vue 对话页 → POST /api/chat/{session_id}
  → SessionRegistry：会话串行、配置刷新、确认与事件通道
  → Agent.chat：核心人格 + 可变表达规则 + Skills + 已保存事实
  → 模型返回文本或 tool call
  → 产品工具白名单 → 业务工具 → SQLite → tool result
  → 模型继续回答 → 会话保存
  → 当前轮记忆评估 / 人格适应 / Skill 学习收尾 → done
```

后台 `ScheduleService` 独立投递明确提醒和订阅，网页关闭时仍保留未读。Skill 学习使用上一轮窗口与本轮反馈；记忆与人格提取使用当前原文，不能混为同一条学习链。

阅读目标：看懂真实请求、执行限制、信息分层和可审计学习。

## 2. 推荐阅读顺序

1. [README](../../README.md) 与 [当前范围 S18](../specs/S18-chat-first-product-scope.md)。
2. [src/mellowday/web_app/__main__.py](../../src/mellowday/web_app/__main__.py)、`app.py`、`service.py`。
3. [src/mellowday/runtime/agent.py::Agent.chat()](../../src/mellowday/runtime/agent.py) 与 `_execute_tool_call()`。
4. [src/mellowday/personal_assistant/tools.py](../../src/mellowday/personal_assistant/tools.py)、`schedule_tools.py` 和 `storage/store.py`（位于 `src/mellowday/`）。
5. [src/mellowday/personal_assistant/persona.py](../../src/mellowday/personal_assistant/persona.py)、`persona_adaptation.py`、`turn_memory.py`。
6. `src/mellowday/runtime/skills/` 下的检索、在线演化、版本和评测模块。
7. [src/mellowday/runtime/sessions.py](../../src/mellowday/runtime/sessions.py)、`session_memory.py`、`memory.py`。

先主链路，再支撑模块；先看怎么运行，再看怎么沉淀。源码链接和具体学习问题见[核心源码阅读指南](核心源码阅读指南.md)。

## 3. 第一站：[src/mellowday/web_app/__main__.py](../../src/mellowday/web_app/__main__.py)

从 [src/mellowday/web_app/__main__.py](../../src/mellowday/web_app/__main__.py) 了解启动参数，再读 `app.py::create_app()` 与 `service.py::SessionRegistry`。

重点追踪：配置来源、`POST /api/chat/{session_id}`、注册表恢复、同会话锁、SSE 事件、确认令牌、abort 和连接断开后的清理。`build_agent()` 实际传入 `product_mode=True`、业务执行器与事实提供器。

读完应知道一次网页请求由谁持有状态，以及主模型结束后为什么还可能出现记忆确认。

## 4. 第二站：[src/mellowday/runtime/agent.py](../../src/mellowday/runtime/agent.py)

### 4.1 先看 `Agent.__init__()`

关注 `product_mode`、`tools`、自定义工具名集合、双协议消息、事实提供器、pending window、后台任务和折叠状态。通用代码里仍有其他分支，必须核对 Web 构造参数。

### 4.2 再看 `Agent.chat()`

它在开始时刷新人格/提示、消费上一学习窗口、检索 Skills；随后调用协议循环，处理文本/工具结果，结束时安排统计、在线学习与保存。

### 4.3 总入口 `_execute_tool_call()`

产品模式先拒绝未授予工具，再处理 `compact_context`、受限 `read_tool_result` 和业务执行器。Plan/MCP/agent/skill 的通用分支不能据此称为网页能力。

### 4.4 辅助路径

查看 `_run_compression_pipeline()`、`_compact_conversation()`、`_persist_large_result()`、`_auto_save()`、`restore_session()`；对应测试见 `tests/web_app/test_execution_trace.py`。

## 5. 第三站：业务工具与存储

### 5.1 先看业务工具定义

主入口在 [src/mellowday/personal_assistant/tools.py](../../src/mellowday/personal_assistant/tools.py) 和 `schedule_tools.py`。Web 构造时移除旧日历写工具、记忆 update/forget，接入区间日历与当前轮记忆处理。

### 5.2 再看执行与授权

`service.py::_session_tool_executor()` 路由 `remember_fact`、日历工具与一般业务工具。`TurnMemory` 重做仅见当前原文的提取，不使用主模型携带历史的拟写内容。

### 5.3 再看存储检查

`storage/store.py` 提供 records 和操作记录；`TurnMemory._commit()` 在事务里比较确认前快照，防止等待期间覆盖用户编辑。停止取消后处理，原轮账本阻止重新学习。

## 6. 第四站：[src/mellowday/runtime/prompt.py](../../src/mellowday/runtime/prompt.py)

看 `runtime/prompt.py::build_system_prompt()` 与 `Agent._refresh_runtime_system_prompt()`。基础提示定义个人助手职责，核心人格从配置读取，可变表达按当前查询匹配。已保存事实和 Skills 有各自注入位置，不从会话折叠自动生成新记忆。

## 7. 第五站：[src/mellowday/runtime/skills/skills.py](../../src/mellowday/runtime/skills/skills.py)

### 7.1 `discover_skills()`

只扫描 `<data>/skills/<name>/SKILL.md`；理解缓存根目录和停用归档的处理，不存在用户级/项目级两套优先级。

### 7.2 `retrieve_relevant_skills()`

按中英文词项匹配 name、description、when-to-use 和正文，使用相关性阈值与 top hits；不是向量数据库。

### 7.3 网页规则注入

`format_retrieved_skill_context()` 只提供候选描述；`Agent._augment_user_message_with_skill_context()` 原样拼入用户消息，未加载正文。网页禁用 skill/fork 工具，因此完整方法投递待修复；后台学习仍可运行，但落盘不等于应用。

## 8. 第六站：[src/mellowday/runtime/skills/online_skill_evolution.py](../../src/mellowday/runtime/skills/online_skill_evolution.py)

这部分是 Skills 自进化入口。

建议按这个顺序看：

1. `extract_online_skill_candidate()`
2. `maintain_online_skill_candidate()`
3. `online_ingest()`

你要抓住的核心不是 JSON schema，而是流程逻辑：

- 用户后续反馈是证据。
- Extractor 最多抽一个候选。
- Maintainer 决定 add / merge / discard。
- 不能把一次性内容写成长期能力。
- 结果会写 provenance。

## 9. 第七站：[src/mellowday/runtime/skills/skill_evolution.py](../../src/mellowday/runtime/skills/skill_evolution.py)

这部分负责 Skill 的落盘、版本和审计。

重点看：

- `create_skill_file()`
- `evolve_skill_file()`
- `record_online_skill_provenance()`
- `record_skill_invocation()`
- `record_skill_usage_judgments()`

重点：
- Skill 文件写到哪里。
- 版本怎么 bump。
- 旧版本怎么留档。
- provenance 和 usage stats 怎么记录。
- 为什么自进化不是直接覆盖 active Skill。

## 10. 第八站：[src/mellowday/runtime/skills/online_skill_eval.py](../../src/mellowday/runtime/skills/online_skill_eval.py)

这是 Skills 质量评测的核心。

建议理解它的四层结构：

```text
provenance
  -> replay pool
  -> rules / LLM judge
  -> candidate variants / champion
```

重点看这些函数：

- `evaluate_online_skill_evolution()`
- `evaluate_online_skill_evolution_async()`
- `_build_replay_pool()`
- `_compile_eval_rules()`
- `_evaluate_rule_async()`
- `_build_candidate_eval_bundle_async()`
- `_set_champion()`

理解的是：

- 为什么评测不是只看一个文件。
- 为什么要先回放历史样本。
- 为什么要区分 current active 和 candidate。
- 为什么 champion 只是本地健康版本记录。

## 11. 第九站：本轮记忆与事实召回

| 类型 | 保存内容 | 更新方式 |
|---|---|---|
| 核心人格 | 身份、背景、基本性格、关系、边界、说话示例 | 用户在设置编辑 |
| 可变人格 | 有证据的场景表达规则 | 当前轮小幅自动演化，可暂停/锁定/撤销/重置 |
| 已保存记忆 | 稳定的用户事实和偏好 | 本轮提取一次；明确授权直接保存，自动候选先确认 |
| Skills | 日程整理等可复用任务方法 | 反馈候选、维护决策、授权后版本化写入 |
| 会话折叠 | 当前任务进度、工作状态和工具经验 | 只帮助该会话继续，不作为永久事实提取来源 |

网页事实以 SQLite `records` 中的 active memories 为唯一来源。`turn_memory.py` 只接收当前用户原文，`memory_turns` 持久记录评估状态；记录、撤销与评估结果在同一事务提交。删除或手工修改后，原轮不能重建或重放旧成功回执。

回答时由 `build_fact_provider()`、`runtime/memory.py::recall_facts()` 召回已经保存的事实，并通知模型失效内容。既有历史文本不被改写，因此不能保证模型绝不引用历史旧值。

阅读次序：`personal_assistant/turn_memory.py` → `tools.py::build_fact_provider()` → `runtime/memory.py::recall_facts()` → `Agent` 的失效事实通知。旧文件记忆兼容函数不是网页事实权威源。

## 12. 第十站：人格适应

阅读 `personal_assistant/persona.py` 和 `persona_adaptation.py`。跟踪当前原文候选、证据验证、核心指纹、额度、候选冲突审查、规则检索、暂停/锁定/撤销/重置。对应 `web_app/persona_routes.py` 与前端 `PersonaAdaptation.vue`。

## 13. 第十一站：日历与定时投递

阅读 `personal_assistant/calendar_store.py`、`schedule.py`、`schedule_tools.py`，再对照 `web_app/calendar_routes.py`。跟踪时间区间、时区重复、单次例外、实例去重、取消前复核、未读持久化，以及报告如何投影到会话。

## 14. 第十二站：会话、事件与前端

- `runtime/sessions.py`：模型会话、完整执行 trace、工具原文和受限引用。
- `runtime/session_memory.py`：结构化折叠状态。
- `runtime/events.py`：ContextVar 事件桥，隔离会话输出。
- `runtime/skills/frontmatter.py`：SKILL 元信息解析与生成。
- `frontend/src/conversation/useConversation.ts`：SSE 事件与停止。
- `frontend/src/calendar/NotificationBubbles.vue`：未读与已读失败恢复。

这些模块决定状态是否真正可保存、可恢复、可回看。
